そもそも⏱ 目安5分

Git / GitHub って何？

Git：ファイルの変更履歴を記録する仕組み（自分のPCの中で完結する）。 「いつ・誰が・何を変えたか」を全部記録できるので、間違えても前の状態に戻せます。

GitHub：Gitの履歴をインターネット上に置いて、みんなで共有・共同編集するためのサービス。 Google Driveでファイルを共有する感覚に近いですが、「誰が何を変えたか」がもっと厳密に記録されます。

今日使う用語⏱ 目安5分

覚えておきたい4つの言葉

リポジトリ (repository)
プロジェクトの中身が入った箱。「フォルダ＋変更履歴」のイメージ
コミット (commit)
「ここまでの変更を記録します」というスナップショット
ブランチ (branch)
本体（main）に影響を与えずに作業できる、自分用の枝分かれ
プルリクエスト (PR)
「この変更を本体に取り込んでください」というお願い・提案

実践2⏱ 目安3分

Organizationへの招待を受ける

1招待メールが届く（届いていなければ声をかけてください）
2メール内の「Join」ボタンから参加を承認する
3GitHub上でこのプロジェクトのリポジトリが見えるようになる

実践3⏱ 目安3分

新しいブランチを切る

1リポジトリのページを開く
2左上の「main」と書かれたブランチ切り替えボタンをクリック
3好きなブランチ名（例: add-自分の名前）を入力して「Create branch」
ブランチは「本体（main）に影響を与えない自分専用の作業スペース」でした（前のスライド参照）。ここではブラウザだけで作れます。

実践4（メイン）⏱ 目安15分

ファイルを作ってPRを出そう

1作ったブランチに切り替えた状態で「Add file」→「Create new file」
2ファイル名の欄に members/自分の名前.md と入力（スラッシュを書くとフォルダも自動でできる）
3自己紹介の内容を書く（名前・学年・好きな山など）
4「Commit changes...」→ 対象ブランチが自分のブランチになっていることを確認して commit
5表示される「Compare & pull request」からPRを作成する
全部ブラウザだけで完結します。ローカルにGitを入れる必要は今日はまだありません（それは次回、実際のコードを触う時に行います）。

PRを出したあと⏱ 目安3分

この後どうなるか

  • 先輩（ゆずこ）がPRの内容を確認（レビュー）する
  • 問題なければ「マージ」されて、本体（main）に取り込まれる
  • 修正が必要な場合はコメントが付くので、直してpushし直す
今回は練習用の自己紹介ファイルなので、気軽に出してもらって大丈夫です。
