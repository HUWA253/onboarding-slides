PR・レビュー実践会

今日は前回コミットした変更を実際にpushして、PRを出して、お互いにレビューし合うところまでやります。

画面下の🧭ボタンを押すと、この講義全体の内容がコピーされます。まず新しいGeminiのチャットに貼り付けてください。分からないページが出てきたら、そのページで🤖ボタンを押して、同じチャットの続きに貼り付けて質問できます。

今日のゴール⏱ 目安2分

今日やること

  • 前回コミットした変更を、自分の作業ブランチとしてpushする
  • GitHub上で実際にPRを出す
  • お互いのPRを読んで、コメントを付け合う
  • 指摘を直して、マージまで体験する
今日のゴールは「自分の変更が人に見てもらえて、mainに取り込まれた」を体験することです。研修はこれで最後です。

今日使う用語⏱ 目安5分

覚えておきたい言葉

PR（プルリクエスト）
「このブランチの変更をmainに取り込んでください」というお願い。第1回はブラウザだけで出しましたが、今回は自分のPCで作った変更を出します
レビュー
他の人が出したPRの中身を読んで、コメントを付けたり「これで良さそう」を伝えたりすること
Approve（承認）
レビューした人が「この内容でmainに入れて良い」と意思表示するボタン
マージ
PRの内容を実際にmainに取り込む操作。Approveされたら押せるようになる

実践1⏱ 目安5分

作業ブランチを作る

前回はmainのまま直接コミットしていたので、まず自分専用のブランチを切ります。

git checkout -b add-自分の名前
これで「今いる場所」に自分専用の名前を付けられました。中身（コミット）は前回のままで大丈夫です。

実践2⏱ 目安5分

ブランチをpushする

git push -u origin add-自分の名前
-uは「このブランチはGitHub上のこの名前と対応してますよ」と覚えさせるおまじないです。次回以降はgit pushだけで済むようになります。

実践3⏱ 目安5分

PRを出す

1pushすると、ターミナルにPR作成用のURLが表示されるので開く（出てこなければGitHub上のリポジトリページを開く）
2「Compare & pull request」ボタンを押す
3タイトルと、何をやったかの説明を書く
4「Create pull request」
第1回はブラウザだけで完結するPRでしたが、今日のは自分のPCで書いたコードが載っています。

実践4（メイン）⏱ 目安15分

お互いにレビューする

1相手のPRのURLを教えてもらい、「Files changed」タブを開く
2気になった行にカーソルを合わせると出る「+」ボタンでコメントを付ける
3読んでみて問題無さそうなら、右上の「Review changes」→「Approve」
最初は「なぜこう書いたの？」くらいの軽い質問でOKです。分からない部分を聞くこと自体がレビューの練習になります。

実践5⏱ 目安10分

指摘を直して再push

コメントをもらったら、ローカルで直して同じブランチにコミット・pushしてみましょう。

git add （直したファイル） git commit -m "レビュー対応" git push
同じブランチにpushするだけで、開いているPRに自動で追加されます。PRを作り直す必要はありません。

実践6⏱ 目安5分

マージする

1Approveされているのを確認する
2PRページ下部の「Merge pull request」を押す
3自分のブランチは役目を終えたので「Delete branch」で消してOK
これで自分の変更がmainに入りました。ここまでが実際の開発の一連の流れです。

うまくいかない時は⏱ 目安3分

詰まったら

  • エラーメッセージが出たら、まずそのまま読んでみる（意外と日本語や分かる単語が混ざっています）
  • フッターの「🤖 詰まったらコピー」で、今のページの内容＋自分の状況をGeminiに聞いてみる
  • それでも分からなければ遠慮なく声をかけてください
