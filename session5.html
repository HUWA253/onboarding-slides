秘密情報とAIの使い方

スプレッドシートのIDやパスワードのような「秘密情報」を、どこに置いて、どう扱うかの約束ごとです。実際の開発に入る前に、一度読んでおいてください。

このページのゴール⏱ 目安2分

今日やること

  • 何が「秘密情報」なのかを知る
  • 秘密情報の置き場所（スクリプトプロパティ）を知る
  • AIにコードを貼るとき、pushするときの確認のしかたを知る
  • うっかり上げてしまったときにどうするかを知る
秘密情報を受け取るのは、この番外編を読んでからにしてもらっています。読んだら先輩に一言伝えてください。

今日使う用語⏱ 目安5分

覚えておきたい言葉

秘密情報
知られると、他人にデータを読まれたり書き換えられたりするきっかけになる値。ID・パスワード・鍵ファイルなど
スクリプトプロパティ
GASのプロジェクトごとに持てる「設定値の保管場所」。コードとは別に保存されるので、gitには上がらない
.env
V1（Flask版）で秘密情報を置いていたファイル。V2ではスクリプトプロパティがこの役割を引き継いでいる
共有設定
Googleのファイルを「誰が開けるか」の設定。「制限付き」なら、IDを知っていても共有された人しか開けない

基本1⏱ 目安5分

何が秘密情報？

1スプレッドシートのID：URLの /d/ と /edit の間の長い文字列（例：1AbCdEfG…xyz）
2GASのデプロイID：AKfycb… で始まる長い文字列
3パスワード、鍵ファイル（.json）、トークン（token.json など）
「IDだけなら共有設定で守られているから平気」ではなく、そもそも外に出さないのが約束です。共有設定のミスと重なったときに、初めて漏れるからです。

基本2⏱ 目安5分

コードには書かない

❌ コードに直接書く（gitに上がる）

const SPREADSHEET_ID = "1AbCdEfG...xyz"

⭕ スクリプトプロパティから読む（gitに上がらない）

const id = PropertiesService.getScriptProperties().getProperty("SPREADSHEET_ID")
コードには「どの名前の設定を読むか」だけを書き、値そのものはスクリプトプロパティに置きます。V1で os.getenv("…") と書いていたのと同じ考え方です。

基本3⏱ 目安5分

スクリプトプロパティに入れる

1ブラウザで script.google.com を開き、第2回で作った自分専用のGASプロジェクトを開く
2左の歯車アイコン「プロジェクトの設定」を開く
3一番下の「スクリプト プロパティ」→「スクリプト プロパティを追加」
4プロパティ名（例：SPREADSHEET_ID）と値を入れて「保存」
スクリプトプロパティはプロジェクトごとに別々です。自分の開発用プロジェクトには、先輩から共有された開発用スプレッドシートのIDを入れます。

AIの使い方⏱ 目安5分

AIに貼る前に確認する

  • GeminiなどのAIにコードやエラーを貼ると、その内容は自分の手元から外に出たことになる
  • 貼る前に、ID・パスワード・メールアドレス・名簿の中身（実在の人の情報）が入っていないか見る
  • 入っていたら "XXXX" のようなダミーに置き換えてから貼る
  • AIが出したコードに、値の直書きが混ざっていないかも確認する
このスライドの「🤖 詰まったらコピー」はスライドの文章だけをコピーするので、そのまま貼って大丈夫です。

pushの前に⏱ 目安5分

addする前に中身を見る

git status git diff --staged
git add . は「このフォルダの中身を全部」です。秘密情報の入ったファイルや、関係ないフォルダまで入ることがあります。たとえば作業フォルダの中で git clone すると、リポジトリの中にリポジトリが入った「マトリョーシカ状態」になり、そのまま git add . すると別リポジトリへの参照として記録されてしまいます。

知っておくこと⏱ 目安3分

一度上げると残り続ける

  • あとのコミットで値を消しても、過去のコミットには残っている
  • そのブランチからPRを作ると、ブランチを消してもPR側に履歴が残り続ける
  • リポジトリは今Privateでも、将来公開する可能性がある
秘密情報が入ったコミットのあるブランチからは、PRを作らないでください。mainから新しくブランチを切り直して、そちらでPRを作ります。

もしものとき⏱ 目安3分

うっかり上げてしまったら

1隠さず、すぐ先輩に伝える（怒りません。早いほど対処が楽です）
2自分で履歴を書き換えたり、--force でpushしたりしない
3パスワードの変更や共有設定の見直しなど、どう対処するかは先輩が判断する

受け取ったら⏱ 目安3分

受け取った秘密情報の扱い

  • Issue・PR・コミットメッセージ・グループのチャットには書かない
  • 他の人に転送しない（必要な人には先輩から渡します）
  • 置き場所は自分のGASプロジェクトのスクリプトプロパティだけ。メモ帳やスクリーンショットに残さない

まとめ⏱ 目安2分

チェックリスト

  • ☐ 秘密情報はスクリプトプロパティだけに置いた
  • ☐ AIに貼る前に、秘密情報と個人情報をダミーに置き換えた
  • ☐ git add の前に git status を見た
  • ☐ 秘密情報が入ったブランチからPRを作っていない
  • ☐ うっかり上げたら、すぐ先輩に伝える
