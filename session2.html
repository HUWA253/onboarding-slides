今日使う用語⏱ 目安5分

覚えておきたい言葉

Docker（ドッカー）
アプリが必要とする道具箱ごと、決まった小さな箱（コンテナ）を用意してくれる仕組み。Node.jsやnpmを自分のPCに直接入れなくても、この箱の中で動かせる
Codespaces（コードスペース）
GitHubが用意してくれる、ブラウザだけで使える開発環境。自分のPCには何も入れずに済む代わりに、無料で使える時間に月ごとの上限がある
clone（クローン）
GitHub上のリポジトリを、自分のPCにまるごとコピーしてくること
clasp（クラスプ）
自分のPCとGoogleアプリスクリプト(GAS)をつなぐための専用ツール。今回はDockerの中から使います
もっと詳しく：Dockerの箱の中身って何？

「Dockerという名前の道具箱（コンテナ）」の中には、主に次の3つの道具が最初からセットされて入っています。

  1. Node.js と npm：このアプリを動かすための「基本エンジン」と、開発に使う色々な部品（ライブラリ）を取り寄せる「便利なカタログ」
  2. clasp：自分のパソコンからGoogleアプリスクリプト(GAS)に接続するための「専用のリモコン」。Googleが公式に配っているツールで、npmのカタログから取り寄せて使っています
  3. Vite（ヴィート）：画面をブラウザに表示するための小さな案内所（Webサーバー）。これもnpmのカタログにある部品の1つです

つまり「アプリのエンジン（Node.js/npm）」＋「Googleと通信するリモコン（clasp）」＋「画面を映す案内所（Vite）」が全部セットになった、このアプリ開発専用の「全部入りお道具箱」が、今回使っているコンテナの正体です。ちなみにVite・claspはどちらも「npmのカタログにある部品」で、Docker自身が特別に作ったものではありません。Dockerは、それらを取り寄せて動かす「箱」を提供しているだけです。

もっと詳しく：なんでDockerを使わないといけないの？

Dockerを使わない場合、参加する人がそれぞれ自分のPCにNode.jsやnpmを個別にインストールする必要があります。バージョンが人によって微妙に違うと「私のPCでは動くのに、あなたのPCでは動かない」という事故が起きやすくなります。

Dockerは「動かす環境」を丸ごと1つの箱にして配ってくれる仕組みです。誰のPCで動かしても中身は完全に同じになるので、この事故を防げます。今回Dockerを使っているのは、まさに「みんなの環境を揃える」ためです。

この後の準備⏱ 目安3分

claspのGoogleログインについて

  • この後、claspというツールからGoogleアカウントへのログインを求められます
  • claspはGoogle自身が公式に配布しているオープンソースのツールで、怪しいものではありません
  • ただし汎用ツールなので、実際にこのアプリが使う範囲より広めの権限（スプレッドシート、ドライブなど）を求めてきます
だからこそ、サークル共有アカウントや自分の本アカウントではなく、開発用に新しく作った捨てアカウントでログインしてください。何かあってもそのアカウント限りで済みます。
途中で「User has not enabled the Apps Script API」のようなメッセージが出ることがあります。その場合は一旦無視してこの先の手順を進めてみてください。それでも詰まる場合はscript.google.com/home/usersettingsで「Google Apps Script API」をONにしてください。

ローカル編 実践1⏱ 目安5分

Dockerを準備する

BかCか、選んだ方だけ進めてください。

BDocker Desktop: https://www.docker.com/products/docker-desktop/ からダウンロードしてインストール
CDocker Engine(WSL2内のターミナルで実行): curl -fsSL https://get.docker.com | sudo sh
3どちらを選んだ場合も、ターミナルで確認
docker --version docker compose version
今回はNode.jsやnpmを自分のPCに直接インストールしません。Dockerさえ入っていれば、道具箱の中身は全部お任せできます。
もっと詳しく：docker と docker compose の違いは？

dockerは「コンテナ（箱）を1つ動かす」ための基本エンジン本体です。docker --versionはこのエンジン自体のバージョン確認です。

docker composeは、その上に乗っている追加ツールで、docker-compose.ymlという設定ファイルを読んで、必要な設定をまとめて起動・停止してくれます。今回使うdocker compose runやdocker compose upは、すべてこちらのツールのコマンドです。docker compose versionはこのツール自体のバージョン確認で、両方入っていないと今回の手順は動きません。

ローカル編 実践5⏱ 目安5分

自分のGoogleアカウントでログイン

ここからはDockerの中でコマンドを実行します。-p 9797:9797はログインの受け取り口（ポート）を一時的に開くためのおまじないです。

docker compose run --rm -p 9797:9797 dev npm run login
既にdocker compose upで画面を表示中の場合は、先にそちらを一度Ctrl+Cで止めてから実行してください（ポートが被るとエラーになります）。
  • ターミナルにURLが表示されます（自動ではブラウザが開きません）
  • そのURLをコピーして、自分のブラウザで開く
  • 自分専用の開発環境用Googleアカウントでログイン→「許可」を選ぶ
サークル共有アカウントではなく、自分専用の開発用アカウントを使ってください。ログイン情報はプロジェクト内の.clasp-credsフォルダに保存され、GitHubには上がりません（.gitignore済み）。

（任意）実際にGASへ反映してみる⏱ 目安10分

clasp pushの効果を見る

ここまでのログイン・GASプロジェクト作成は、実は今日見たローカルの画面表示そのものには使っていません。「じゃあ何のためにやったの？」と思った人は、ここで実際に試してみてください。

docker compose run --rm dev npm run push docker compose run --rm dev sh -c "cd src && npx clasp deploy"
2つ目のコマンドの実行結果に - （英数字の文字列） @1. のような行が出ます。その英数字部分をコピーして、下のURLの◯◯に当てはめてブラウザで開いてください。
https://script.google.com/macros/s/◯◯/exec
さっき見たのと同じ画面が、今度はGoogleのサーバー上で動いているのが確認できたら成功です。これが今日設定したclaspの本当の役割です。
